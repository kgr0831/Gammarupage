# 겜마루 운영 플랫폼 · 운영자금 에이전트 기획안

작성일: 2026-10-05

상태: 러프 기획 v0.4 — HTML 업로드와 저장되는 진행 기록·다음 조사 반영

> 이 문서는 전체 개발 방향의 기준이다. 최신 구현은 [Vercel HTML 보관함 안내](vercel-html-reports.md), [dots 운영 지침](dots-daily-brief.md), [Design.md](../Design.md)를 따른다. 아래 장기 계획을 모두 구현했다는 의미는 아니다.

### 최신 결정과 구현 범위

- 2026-10-06 개인용 전환: 아래 동아리 공용 계획을 대신해 개발·AI·IT 공모전·채용과 미국 주식·ETF 일일 정보로 운영한다. 보고서는 관리자와 승인된 소유자만 읽고 수정하며, 새 보고서 알림은 본인 Discord DM으로만 보낸다.
- 기존 HTML·진행 기록은 보존한다. 동아리 지원 항목은 개인 추천에서 제외하고 공모전/트레이딩/채용을 구분한다. 개인 자격·경력·지역은 아직 미확정이므로 적합성을 추정하지 않는다. 지원서 제출·자동 매매는 포함하지 않는다.
- 이하 내용은 초기 동아리 운영 방향의 기록이다. 현재 설정은 [개인 조사 프로필](personal-brief-profile.md)과 [dots 지침](dots-daily-brief.md)을 따른다.

- 2026-10-06 추가: 신규 정보와 검토 전·보류·진행 중인 항목을 조사한다. 완료·안함은 중요한 새 변화가 있을 때만 다시 보고한다.
- HTML 한 파일에 항목별 ID·공식 원문·추천 행동을 비실행 JSON으로 포함한다. 사이트가 진행 관리 UI를 만들고 상태·메모를 Private Blob에 저장한다. 동일 항목의 상태는 보고 날짜가 바뀌어도 유지된다.
- 진행 기록은 동아리가 공유하며 관리자와 승인된 구독자 모두 수정한다. dots는 다음 조사 전에 `/reports/research-state`를 읽고 최신 결정·보류 사유를 반영한다. 상태 선택은 외부 신청·발송 승인이 아니다.
- 본문은 모바일 16px 이상, 한 열 배치, 한국어 요약 우선으로 개선한다. 기존 보고서도 원본을 보존하면서 읽기 스타일을 적용한다.

- 일일 보고서 알림은 새 Discord 서버의 **데일리 스크럼** 채널에 날짜·제목·짧은 요약·링크를 한 번 게시하는 방식으로 변경한다. 개인 보고서 DM은 중단하며, 로그인·승인 확인 DM과 웹사이트 열람 승인은 유지한다.
- 수집 대상은 채용공고가 아니라 **외부 후원·운영자금·겜마루에 도움이 되는 정보**다.
- 기존 배포 주소는 **https://gammarupage.vercel.app/** 이다. 랜딩 메뉴에는 링크를 추가하지 않고 같은 도메인의 `/reports`에서 이용한다.
- dots는 클라우드에서 수집·보고를 수행한다. 개발 용도로 맡기는 작업이 아니다.
- dots가 Design.md를 따라 완성한 HTML을 `/reports/upload`에 올린다. 미리보기 확인 후 Private Blob에 저장하고, `/reports` 누적 목록과 `/reports/YYYY-MM-DD` 개별 URL을 제공한다. 최초 기능 배포 이후 일일 업로드에는 재배포가 필요 없다.
- 일반 회원의 Discord 로그인, 이름 입력·구독 신청, 관리자 아이디/비밀번호 로그인,
  이름·프로필 기반 승인/취소, 승인 회원 전용 보고서, 동의한 회원 대상 링크 DM을 구현했다.
- 구독 승인은 `/reports/admin`에서 관리한다. 외부 행동 승인과 팩트챗 자동 대체는 이전 독립 시제품에 있으며 Vercel 경로에 아직 연결하지 않았다.
- 수집·보고의 주 경로는 계정의 dots 클라우드다. 팩트챗을 2순위로 사용하는 요구는 유지하며 Vercel 연동은 후속 작업이다.
- Private Blob 연결·최초 기능 배포·OAuth 연결·첫 보고서 발행·실제 DM 전송을 확인했다. dot 예약 등록과 클라우드 첫 자동 실행은 아직 완료되지 않았다.
- 아래 표의 `/newsletter`, `/account`, `/admin/subscriptions`는 초기 경로 초안이다.
  현재 경로는 `/reports`, `/reports/account`, `/reports/admin`, `/reports/upload`다. 별도 스크럼과 랜딩 CMS는 후속 범위다.

## 1. 목표

기존 겜마루 랜딩 페이지를 바탕으로, 동아리 소개와 운영 기능을 한 웹사이트에서 제공한다.

- 매일 외부 운영자금 확보에 도움이 되는 정보를 찾아 웹 뉴스레터로 제공한다.
- AI가 지원 기회별 다음 행동을 추천하고, 어드민이 승인하면 해당 작업을 실행한다.
- 뉴스레터와 데일리 스크럼은 **승인된 구독자 전용**이다.
- Discord 봇은 구독자에게 **웹페이지 링크를 DM으로 전달**한다.
- 개인 PC가 꺼져 있어도 탐색·리포트 생성·알림이 진행되도록 원격 실행 환경을 마련한다.

동아리 소개와 판단의 기본 자료는 [`gammaruInfo.md`](../gammaruInfo.md)를 사용한다. 겜마루를 일반 기업으로 가정하지 않고, 숭실대학교 중앙 게임개발동아리라는 조건을 반영한다.

| 뉴스레터 보기 | 불가 | 불가 | 가능 | 가능 |
| 데일리 스크럼 보기 | 불가 | 불가 | 가능 | 가능 |
| 정기 DM 수신 | 불가 | 불가 | 수신 동의 시 가능 | 어드민이라는 이유만으로 자동 구독하지 않음 |

| 사이트 콘텐츠 관리 | 불가 | 불가 | 불가 | 가능 |
| 자금조달 작업 승인·실행 | 불가 | 불가 | 불가 | 가능 |

- Discord 로그인 성공과 구독 승인은 서로 다른 단계다.
- 어드민 권한은 Discord 표시 이름이나 클라이언트가 보내는 역할 값으로 부여하지 않는다.
- 메뉴를 숨기는 것 외에 서버에서도 매 요청마다 권한을 검사한다.
- 링크를 전달받아도 로그인·승인 확인 없이 전용 콘텐츠를 읽을 수 없다.
- 구독 해지·승인 취소 시 기존 로그인 세션이 남아 있어도 열람과 후속 DM을 차단한다.

## 5. 구독 신청과 승인 흐름

1. 사용자가 같은 사이트의 로그인 페이지에서 Discord로 로그인한다.
2. Discord 계정 정보와 신청 이름을 확인하고 구독을 신청한다.
3. 신청은 `승인 대기` 상태로 저장된다. 이 상태에서는 전용 콘텐츠를 열람할 수 없다.
4. 어드민이 아이디·비밀번호로 로그인한다.
5. 신청자 이름, Discord 표시 이름·프로필 이미지·사용자 ID, 신청 시각을 확인한다.
6. 어드민이 승인 또는 거절한다.
7. 승인된 사용자는 뉴스레터·스크럼을 볼 수 있고 정기 DM 대상이 된다.
8. 사용자는 구독을 해지할 수 있고, 어드민은 승인 권한을 회수할 수 있다.

상태 초안: `미신청 → 승인 대기 → 승인 / 거절`, 이후 `해지 / 권한 회수`.

어드민 목록에는 대기·승인·거절·해지 상태별 필터와 처리 기록을 제공한다. 구독 신청이 여러 번 들어와도 같은 Discord 사용자 ID에 대한 중복 회원을 만들지 않는다.

**이름 정책은 미정이다.** 신청자가 입력하는 실명과 Discord 표시 이름을 함께 사용할지, Discord 표시 이름만 사용할지 확정해야 한다.

## 6. 뉴스레터와 일일 탐색

### 탐색 범위

- 대학 동아리·학생팀 활동 지원
- 게임 개발·창작 지원 및 공모전
- 게임잼·행사 후원과 기업 협찬
- 문화재단·청년 활동 지원
- 개발 도구·공간·물품·서비스 크레딧 등 현물 지원

동아리 전체 운영비, 개별 학생 지원, 제작팀 지원을 구분한다. 현금, 현물, 수상 조건부 상금을 합쳐서 같은 운영자금처럼 표시하지 않는다.

### 리포트에 담을 정보

- 조사 날짜와 요약
- 공고명·주최기관·공식 원문 링크
- 지원 종류·내용·규모와 사용 제한
- 신청 대상, 겜마루와의 적합성, 확인이 필요한 조건
- 마감 날짜·시간, 준비 서류, 자부담·정산 조건
- 추천하는 다음 행동과 우선순위
- AI가 확인하지 못한 부분과 근거 요약

사업자등록·법인격·개인 자격 등이 필요한 공고는 조건을 분명히 표시한다. 확인되지 않은 금액·담당자·마감일을 만들어 넣지 않는다. 유효한 공고가 없으면 조사한 범위와 결과 없음 상태를 보여준다.

### 일일 처리 흐름

현재 Vercel 연결 흐름: `dots 예약 실행 → 공식 원문 조사 → Design.md 기반 HTML 작성 → 업로드·미리보기 → 비공개 저장·누적 목록 → 승인·수신 동의한 구독자에게 링크 DM`.

팩트챗 2순위 대체는 전체 기획에 남아 있지만 현재 Vercel 경로에는 자동 연결되어 있지 않다.

정확한 탐색·발송 시각은 미정이다. 초기 프로토타입은 한국시간 오전 9시를 기본값으로 사용한다. AI 사용량 한도, 로그인 만료, 검색 실패를 기록하고 실패를 정상 리포트로 표시하지 않는다.

## 7. Discord 봇의 역할

- 주 용도는 **승인된 구독자에게 뉴스레터 링크를 DM으로 보내는 것**이다.
- 구독 신청과 승인 관리는 웹사이트를 기준으로 한다.
- 서버 전체 인원이나 단순 로그인 사용자를 자동 발송 대상에 넣지 않는다.
- DM 발송 직전에 승인·해지·수신 동의 상태를 다시 확인한다.
- DM에는 민감한 운영 내용이나 승인용 비밀 토큰을 포함하지 않는다.
- 사용자별·리포트별 발송 기록을 남겨 중복 전송을 방지한다.
- DM 차단·권한 부족·속도 제한·결과 불명 상태를 기록하고 어드민이 확인할 수 있게 한다.

앞서 검토한 `/구독`·`/구독해지` 명령은 필수 범위로 확정하지 않았다. 추가한다면 같은 신청 상태를 사용하고, 봇 명령만으로 어드민 승인을 건너뛸 수 없게 한다. MVP에서는 웹 신청을 먼저 완성한다.

## 8. 데일리 스크럼

**승인된 구독자 전용 페이지라는 점은 확정했다.** 내용과 작성 주체는 아직 결정하지 않았다.

검토 중인 두 방향:

1. 자금조달 운영 현황: 오늘 할 일, 진행 중인 지원, 막힌 일, 완료 결과.
2. 구성원 활동 스크럼: 구성원이 전날 진행·오늘 계획·도움이 필요한 일을 작성.

초기 화면 초안은 `날짜 / 오늘 할 일 / 진행 상황 / 막힌 일 / 담당자`다. 구독자가 직접 작성할 수 있는지, 어드민만 관리하는지와 다른 구성원의 기록을 볼 수 있는 범위는 후속 결정 사항이다.

## 9. AI 추천과 작업 실행 승인

구독 승인은 콘텐츠 접근 권한이다. 지원기관 연락·신청 등 외부 행동을 허용하는 작업 승인은 별도로 관리한다.

1. AI가 지원 기회와 구체적인 다음 행동을 추천한다.
2. 필요한 문서·문의 메일·준비 목록의 초안을 만든다.
3. 어드민이 대상, 본문, 첨부, 필요한 정보와 예상 비용을 확인한다.
4. 어드민이 특정 작업의 특정 내용을 승인한다.
5. 시스템이 승인된 범위의 작업을 실행하고 결과를 기록한다.

초기 자동 실행 범위는 제안서·신청 준비 문서 생성과 승인된 이메일 발송이다. 기관별 지원 포털 제출, 계약, 결제, 본인확인 등은 별도 연동과 실행 범위 확정 후 추가한다.

초안 수정 시 재승인이 필요하다. 중복 클릭으로 두 번 실행되지 않아야 하고, 발송 결과가 불명확할 때 무조건 다시 발송하지 않는다. 외부 연락처와 이메일 초안 등 운영 자료는 구독자 리포트와 구분해 어드민만 볼 수 있게 한다.

## 10. AI·계정·원격 운영 방향

- **1순위:** 사용자의 Codex 계정.
- **2순위:** 숭실대 팩트챗 서비스의 API Gateway.
- 정상적으로 검색했지만 결과가 없는 경우와 제공자 장애를 구분한다.
- 팩트챗을 연결해도 기본 Codex 계정 설정을 일괄 대체하지 않는다.
- 팩트챗 API 사용 비용과 Codex 구독 사용량을 별도로 취급한다.

팩트챗 서비스: <https://ssu.factchat.bot/dashboard/developers>

사용자가 지정한 설정 안내: <https://docs.mindlogic.ai/agent-setup/prompt.md>

웹사이트는 기존 Vercel 배포를 사용한다. Next 서버 경로에서 로그인·권한·업로드를 처리하고 Private Blob에 HTML·목록·회원 상태를 저장한다. 개인 PC의 디스크나 상시 실행 프로세스에 의존하지 않는다.

dots는 사용자가 선택한 수집·보고 실행 환경이다. 클라우드 브라우저에서 업로드 전용 계정으로 로그인하고 반복 일정을 저장한다. 사이트 발행 후 Vercel 함수가 링크 DM을 처리하며, 남은 대기는 dots가 등록 화면에서 이어서 처리할 수 있다. 실제 계정에서 dots 접근·파일 업로드·로그인 유지·예약 실행을 확인해야 한다. 현재 dots 연결이나 반복 작업 예약은 완료되지 않았다.

## 11. 어드민 사이트 관리 범위

어드민은 한 관리 영역에서 구독자, 페이지 콘텐츠, 자금조달 작업을 관리한다.

러프 개발의 우선 범위:

- 랜딩: 소개 문구·공지 등 자주 바뀌는 콘텐츠 관리.
- 뉴스레터: 날짜별 리포트 조회와 운영 상태 관리.
- 스크럼: 선택한 운영 방식에 맞는 항목 관리.
- 구독자: 신청 명단, 승인·거절·권한 회수, DM 상태 관리.
- 자금조달: 탐색 기록, 실행 제안, 승인과 실행 결과 관리.

페이지 전체를 자유롭게 편집하는 CMS, 게임 아카이브의 모든 항목 편집, 어드민 계정 추가·권한 위임까지 포함할지는 미정이다. 우선 관리해야 할 항목을 정해 작은 범위부터 구현한다.

## 12. 데이터와 보안의 기본 방향

필요한 데이터: 회원·Discord 프로필, 구독 신청/심사 상태, 로그인 세션, 뉴스레터, 스크럼, 사이트 콘텐츠, AI 작업/승인, DM 발송 결과, 관리 변경 기록.

- 회원 상태와 작업 승인 상태를 따로 저장한다.
- Discord 로그인은 공식 OAuth 흐름과 서버 검증을 사용한다. 봇 토큰과 OAuth Client Secret은 별개다.
- 어드민 비밀번호는 적절하게 해시해 관리하고, 로그인 시도 제한과 안전한 세션을 적용한다.
- 토큰·API 키·세션 값은 소스, Markdown, 브라우저 번들, 일반 로그에 넣지 않는다.
- 비공개 리포트는 정적 빌드 결과물이나 공개 파일로 내보내지 않는다.
- 공고 원문과 AI 출력은 데이터로 처리하고, 그 안의 지시를 실행 권한으로 해석하지 않는다.
- 탈퇴 시 개인정보 삭제 범위와 승인·발송 기록 보관 기간은 후속 결정한다.

## 13. 러프 개발 순서와 확인 기준

### 1단계 — 같은 사이트의 페이지 구성

기존 랜딩을 유지하면서 로그인·어드민·뉴스레터·스크럼 경로와 공통 메뉴를 만든다. 첫 화면 작업에는 명확히 표시한 가상 데이터를 사용할 수 있다.

확인 기준: 각 페이지의 직접 접근·새로고침·모바일 탐색이 가능하고 공통 디자인이 이어진다.

### 2단계 — 로그인과 구독 승인

어드민 아이디·비밀번호 로그인, Discord 로그인, 신청 폼, 신청자 명단, 승인·거절·해지를 구현한다.

확인 기준: 미승인 사용자는 뉴스레터·스크럼 API에도 접근하지 못하고, 승인·취소가 기존 로그인 세션에 즉시 반영된다.

### 3단계 — 뉴스레터와 구독자 DM

기존 탐색 프로토타입을 통합 사이트에 연결하고 날짜별 리포트를 저장한다. 승인된 사용자에게만 DM을 발송한다.

확인 기준: 대기·거절·해지 사용자에게 발송되지 않고, 같은 날짜의 링크가 중복 전송되지 않는다.

### 4단계 — 스크럼과 페이지 관리

스크럼의 용도·작성 권한을 확정해 구현하고, 랜딩 등 선택한 페이지의 관리 항목을 연결한다.

확인 기준: 어드민이 저장한 콘텐츠가 해당 페이지에 반영되고 일반 구독자는 관리 기능을 사용할 수 없다.

### 5단계 — 작업 승인과 원격 운영

AI 추천·초안·작업 승인·실행 결과를 연결하고 원격 서버에 배포한다.

확인 기준: 승인한 내용만 한 번 실행되고, 개인 PC를 끈 상태에서도 원격 서버의 일일 탐색과 DM이 작동한다.

## 14. 현재 상태와 남은 결정

### 현재 확인된 상태

- 기존 Next.js 겜마루 랜딩과 게임 아카이브가 있다.
- `funding/`에 별도 HTML 보드, 탐색 제공자 구조, 리포트 저장, 작업 승인·실행의 초기 프로토타입이 있다.
- 초기 프로토타입·회원 포털과 새 Vercel 업로드 경로의 자동 테스트·브라우저 검증을 수행했다. 실제 외부 계정 연동 검증과는 구분한다.
- 제공받은 팩트챗 키로 모델 목록 조회에 성공했다. 실제 일일 검색의 운영 검증은 아직 하지 않았다.
- 제공받은 Discord 봇 정보로 봇 인증과 애플리케이션 정보 일치를 확인했다. 실제 구독자 DM은 아직 보내지 않았다.
- 비밀값은 로컬 비공개 설정에 저장했고 이 기획안에는 포함하지 않았다.
- Vercel용 Discord OAuth 로그인, 어드민 구독 승인, HTML 업로드·미리보기, 구독자 전용 누적 목록·날짜별 HTML, 링크 DM 전송 큐를 구현했다. 이전 시제품의 SQLite 데이터·팩트챗 대체·외부 행동 승인은 자동 이관하지 않는다. 랜딩 콘텐츠 관리와 별도 스크럼은 아직 구현 전이다.
- Discord OAuth Client Secret과 로그인 리디렉션 설정이 추가로 필요하다.
- 기존 Vercel 사이트는 운영 중이다. 새 보고서 기능의 저장소 연결·배포와 dots 정기 운영은 아직 시작하지 않았다.

### 후속 결정 사항

1. 신청자 이름: 실명 입력 여부와 표시 방식.
2. 데일리 스크럼: 자금조달 현황인지 구성원 활동 기록인지, 작성·열람 범위.
3. 어드민: 초기 계정, 계정 수, 비밀번호 변경·복구 방식.
4. 사이트 관리: 랜딩과 각 페이지에서 수정할 항목의 범위.
5. 알림: 일일 탐색·DM 발송 시각, 스크럼 링크 포함 여부, 실패 시 처리 방식.
6. 운영 예산: 서버·도메인·API 예산과 팩트챗 대체 모델.
7. 자금조달 조건: 목표 금액·사용 용도·동아리 대표 정보·신청 자격 확인 자료.
8. 개인정보와 운영 기록의 보관·삭제 정책.
