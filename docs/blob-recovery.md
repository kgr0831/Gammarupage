# 보고서 저장소 사용량 초과 대응

## 2026-10-12 확인 결과

개인·겜마루 보고서가 함께 사용하는 Private Blob의 관리 API 상태가
`limits-exceeded-suspended`, `billingState: suspended`, `usageQuotaExceeded: true`였다.
저장소 메타데이터에는 파일 44개, 1,682,045바이트가 남아 있었고, 토큰 만료 상태는 아니었다.
파일 본문을 읽을 수 없어 개별 보고서와 진행 기록의 무결성까지 확인한 것은 아니다.

팀은 Hobby 요금제다. 정확히 어느 사용량 항목이 초과됐는지와 해제 날짜는 아직 미확인이다.
`vercel usage`는 이 팀의 해당 기간에 청구 데이터를 제공하지 않았다.
파일 용량이 작다는 이유로 읽기·쓰기 요청 한도를 배제하면 안 된다.

## 재발 방지 변경

- 기존 60초 간격 봇 조회는 매번 `useCache: false`로 원본 상태를 읽었다.
  30일 내내 켜져 있으면 빈 큐 확인만으로 약 43,200회다.
- 이제 빈 큐 확인에는 인증된 **Private Blob 내부 CDN 캐시**를 사용한다.
  Vercel 함수 프로세스가 바뀌어도 같은 플랫폼 캐시를 활용하며 별도 의존성은 없다.
- 캐시에서 작업 후보가 보이면 최신 상태를 다시 읽고 ETag 조건부 쓰기로 점유한다.
  실제 발송 직전에도 권한과 버전을 확인한다. 오래된 캐시로 발송을 승인하지 않는다.
- 로그인, 열람 권한, 상태·메모 변경, 발행 및 조사 자료는 계속 최신 상태를 읽는다.
  웹 응답은 계속 `private, no-store`이며 사용자 브라우저에 상태를 캐시하지 않는다.
- 변경되지 않는 해시별 HTML만 저장소 캐시를 사용하고 내용 해시를 검증한다.
- 저장소 읽기 제한·정지 오류에는 사용량과 저장소 상태 확인 안내를 보여 준다.
  읽기 SDK의 HTTP 오류만으로 토큰 만료나 한도 초과를 단정하지 않는다.

공식 문서상 덮어쓴 파일의 캐시 반영에는 최대 60초가 걸릴 수 있다.
기존 60초 봇 조회 주기를 더하면 정상 운영에서도 새 알림 확인까지 약 2분 걸릴 수 있다.
캐시 적중 시 Blob Simple Operations가 발생하지 않지만 실제 읽기·쓰기는 계속 사용량을 소비한다.
이 변경은 무료 한도 내 운영을 보장하거나 이미 정지된 저장소를 해제하지 않는다.
서버 측 변경이므로 기존 Dishost 봇 파일을 다시 올릴 필요는 없다.

## 복구 절차

1. Vercel 팀의 Usage와 Storage에서 초과 항목·해제 시점을 확인한다.
2. Hobby 사용량 초과는 공식 정책상 한도 해제를 기다리거나 Pro로 변경해야 한다.
   비용이 발생하는 요금제 변경은 소유자 승인 후에만 진행한다.
3. 기존 저장소를 삭제하거나 빈 저장소로 교체하지 않는다. 토큰 재발급은 사용량 제한을 해제하지 않는다.
4. 저장소 활성화 후 두 발행자 로그인과 최신 조사 자료 읽기를 확인한다.
   기존 보고서 날짜·버전, stateVersion, 진행 상태·메모와 채널 대상을 대조한다.
5. dots는 최신 자료를 다시 읽고 오늘 보고서 중복 여부부터 확인한 후 미발행 작업만 재개한다.
   실제 보고서 날짜·버전에 해당하는 알림의 `sent` 기록을 확인해야 완료다.
   `uncertain`을 강제로 재전송하거나 기존 보고서를 자동 재발행하지 않는다.
