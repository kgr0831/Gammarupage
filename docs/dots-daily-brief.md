# dots 일일 수집·HTML 보고 작업

수집 대상은 **겜마루 동아리가 외부에서 직접 확보할 운영비·후원 물품·장비·공간·단체용 서비스 지원**이다.
이 문서는 운영용 dot에게 줄 지시문이며, 개발 작업 지시문이 아니다.
배포 대상은 **https://gammarupage.vercel.app/** 이다.

## 수집 기준 — 동아리가 실제로 받을 자원

2026-10-06 운영자 피드백을 반영한 기준이다. 기존의 포괄적인 '도움되는 정보'보다 이 기준이 우선한다.
게임·대학생·무료·마감 임박이라는 키워드만으로 추천하지 않는다.

### 우선 찾을 것

1. 겜마루 또는 학생 동아리 대표 명의로 신청할 수 있는 운영비·활동비·행사비 지원.
2. **겜마루가 여는** 게임잼·발표회·스터디·교류 행사에 기업이 제공하는 금전·간식·상품·물품 후원.
3. 동아리가 함께 사용할 PC·모니터·개발 장비의 기증·대여, 동아리 행사에 쓰는 공간·시설 지원.
4. 학생 **단체**에 제공하는 협업 서비스·조직용 라이선스·서버 자원 지원. 개인 계정 혜택과 구분한다.

현금과 현물을 우선한다. 서비스 지원은 실제 동아리 공동 운영에 쓸 수 있을 때만 보조 후보로 다룬다.
무료 상품의 정가를 현금 확보액으로 합산하거나, 이미 비용을 지출한다고 가정해 절감액을 만들지 않는다.

### 추천 전에 모두 확인할 것

- **제공자와 수혜 주체:** 누가 자원을 제공하며, 겜마루 같은 대학 동아리 또는 그 대표가 받을 수 있는가?
- **확보할 자원:** 현금 얼마, 어떤 물품 몇 개, 장비 대여 기간, 공간 사용 시간, 단체 서비스 권한 중 무엇인가?
- **사용처:** 동아리 공동 운영이나 동아리가 개최하는 어느 활동에 사용할 수 있는가? 새 사업·창업을 가정하지 않는가?
- **확보 경로:** 현재 신청 페이지·신청 기간, 또는 후원 제안을 받는 공식 문의 창구가 있는가?
- **대가와 조건:** 자부담·정산·홍보·로고 노출·결과 보고·반납·이용 제한은 무엇인가?

공식 근거로 자원과 동아리 수혜 가능성을 확인한 것만 '신청 검토'에 넣는다.
자격이나 신청 경로를 확인하지 못한 것은 추천으로 승격하지 말고 확인할 질문을 적는다.
단순 기업 홈페이지나 과거 보도자료는 현재 후원 접수 창구의 근거가 아니다.

### 기본 제외

- 창업경진대회·외부 게임 개발 대회·해커톤 등 **참가·수상·새 작품 제작을 해야 상금이나 혜택을 받는 기회**.
  게임 관련이어도 동아리 운영자금 조달과 동일하지 않다. 운영자가 별도로 요청한 대회만 예외로 검토한다.
- 일반 무료 행사·세미나·컨퍼런스·교육·멘토링·네트워킹, 참가자 경품·추첨 이벤트.
- 개인 학생 계정에 귀속되는 개발 도구·클라우드 크레딧·학생 할인·장학금.
  개인 혜택을 동아리 소유 자원으로 계산하거나 계정 공유·양도를 가정하지 않는다.
- 일반 게임 배포·데모 등록·포트폴리오 공개 안내, 채용, 업계 뉴스.
- 사업자·법인·창업팀·거주지 등 필수 조건이 겜마루에 해당한다는 근거가 없는 지원.

주최 행사에 대한 후원 공고라면 '누가 행사에 참가하는가'가 아니라 '누가 행사를 운영하며 자원을 받는가'로 판단한다.
참가비 무료와 동아리 지원금 지급을 혼동하지 않는다.

### 제안 후보와 이어서 검토할 항목

- 현재 모집 중인 지원과 **기업 후원 제안 후보**를 분리한다. 후원 후보를 확보된 자원이나 신청 가능한 공고로 표시하지 않는다.
- 후원 후보는 유사 동아리·행사 후원 근거, 공식 제안 창구, 요청할 구체 품목과 제공할 협력 내용을 확인한 경우 최대 2개다.
  과거 사례만 있고 창구가 미확인이라면 처음 한 번 '추가 확인'에 짧게 남기고 매일 다시 싣지 않는다.
- 검토 전·보류·진행 중도 이 수집 기준을 먼저 통과해야 한다. carryForwardIds 전체를 매일 복사하지 않는다.
- 사용자가 '안함'에 남긴 범위 제외 사유를 우선한다. 단순 마감 임박·날짜 변경으로 제외 항목을 되살리지 않는다.
- 새 접수·지원 조건 변경·실제 후원 응답·메모에 따른 해결 사항이 없으면 기존 혜택을 다시 나열하지 않는다.
- 적합한 신규 자원이 없으면 **'오늘 확인된 신규 자원 없음'**이라고 보고한다. 개수를 채우지 않는다.

## 최초 연결

1. [Vercel 연결 안내](vercel-html-reports.md)에 따라 Private Blob·로그인 환경변수·Discord OAuth를 연결하고 보고서 기능을 최초 배포한다.
2. dot의 **클라우드 컴퓨터** 브라우저로 `https://gammarupage.vercel.app/reports/login/publisher`를 연다.
3. 비공개 로그인 또는 브라우저 인계를 요청하게 하고 사용자가 업로드 전용 키를 직접 입력한다.
   키를 대화·Markdown·HTML에 붙이지 않는다. 관리자 비밀번호나 Discord 봇 토큰을 dot에게 주지 않는다.
4. 이 계정은 HTML 등록·자신의 미리보기·알림 처리 전용이다. 회원 명단·구독 승인·외부 메일 발송 권한은 없다.
5. 클라우드에서 HTML 파일을 만들고 파일 선택 입력에 업로드할 수 있는지 실제로 확인한다.
   로컬 PC의 파일 경로를 요구하는 흐름으로 바꾸지 않는다. 기능이나 권한이 부족하면 그 단계를 미완료로 알린다.
6. 아래 지시문으로 작업을 맡기고 **Scheduled**에서 저장된 일정, 시간대, 다음 실행 시각을 확인한다.
   이 저장소가 dot의 일정을 자동 등록하지는 않는다. 오전 9시 KST는 초기 권장값이다.

업로드 로그인 세션은 최대 30일이다. 만료나 추가 인증이 필요하면 사용자가 비공개 로그인 흐름에서 다시 로그인한다.
클라우드 실행은 개인 PC가 꺼져 있어도 가능하지만, 무기한 무인 로그인을 보장하지 않는다.

### 브라우저에서 조사 자료 읽기

로그인 후 `https://gammarupage.vercel.app/reports/upload?guide=1`을 열면 작업 지침·동아리 정보·Design.md·진행 기록을 **하나의 HTML 페이지**에서 읽을 수 있다. 업로드 화면의 자료 링크들도 이 페이지로 연결된다.
텍스트·JSON 주소에서 `ERR_BLOCKED_BY_CLIENT`가 나면 이 HTML 보기를 사용한다. 기존 주소의 접근 권한을 해제하거나 로그인 키를 URL에 넣지 않는다.
`#research-state`의 `research-state-json` 영역은 `/reports/research-state`와 같은 전체 JSON이다. 최신 `stateVersion`, `known`, 메모, 이전 보고서 목록을 여기서 확인할 수 있다. 조사 시작 시와 발행 직전에 페이지를 새로고침한다.

이 서비스는 **겜마루 동아리용**이다. 개인 브리핑은 별도 서비스이며 현재 작업과 예약을 바꾸지 않는다.
동아리 HTML의 `audience`와 `category`는 생략할 수 있다. 명시한다면 `audience: "club"`, `category: "support"`를 사용한다.
`audience: "personal"`로 바꿔 검증을 통과시키려 하지 않는다.

파일 선택을 사용할 수 없으면 업로드 화면의 **파일 대신 HTML 내용 붙여넣기**를 펼치고,
**HTML 전체 내용**에 완성한 문서 전체를 입력한다. 파일과 붙여넣기 중 하나만 사용한다.
두 방식은 같은 인증·2MB 제한·진행 기록 검증·미리보기·발행 확인을 거친다.
자료 열람, 폼 입력, 미리보기와 발행은 사이트의 실행 JavaScript 없이 동작한다.
클라우드 브라우저 도구 자체가 승인을 거절하면 사이트 오류와 구분해서 정확한 동작·오류를 보고한다.
사이트에 키를 노출하거나 도구의 승인 절차를 우회하지 않는다.

## dot에게 줄 지시문

아래 블록 전체를 기존 예약의 작업 지시로 교체한다. 겜마루 정보까지 포함한 독립된 프롬프트이며, 이전 대화의 설명을 요구하지 않는다.

```text
이번 요청은 기존 ‘겜마루 일일 지원 보고’의 작업 지시 교체야.
아래 1~7절 전체를 기존 매일 오전 9시(Asia/Seoul) 예약의 실행 지시로 저장해줘.
예약 갱신과 마지막 확인 요청은 이번 한 번만 수행하고, 정기 실행에서는 1~7절을 수행해줘.
중복 예약은 만들지 마.

[1. 너의 역할과 목표]
너는 ‘겜마루 외부 자원 확보 담당자’야.
개인 PC가 꺼져 있어도 수행할 수 있도록 너의 클라우드 환경을 사용해줘.
겜마루 동아리가 직접 확보할 운영비·후원 물품·장비·공간·단체 서비스 지원을 조사하고,
운영진이 지원 신청이나 후원 제안을 판단할 수 있는 일일 HTML 보고서를 작성·등록해줘.
각 추천은 “누가, 겜마루에 무엇을, 어떤 조건으로 제공하며, 우리는 다음에 무엇을 하면 되는가”에 답해야 해.

[2. 겜마루 동아리 정보]
- 겜마루(GAMMARU)는 1995년에 시작된 숭실대학교 중앙 게임개발동아리야.
- 다양한 전공의 학생들이 기획·아트·프로그래밍·사운드 역할로 협업해 플레이 가능한 게임을 만들어.
- 자체 여름·겨울 공모전에서는 방학 동안 제작한 게임의 기획·중간 과정·최종 결과물을 발표해.
- 자체 게임잼, 보드게임잼, 개발 스터디, 지식 발표회, 선배·현업자·타 대학 동아리와의 교류 활동이 있어.
- 공개 소개에는 Unity·Unreal 등을 다루는 스터디와 72시간 게임잼이 기록돼 있어.
- 작품 아카이브와 활동 기록은 후원 제안의 근거로 쓸 수 있어.
  소개: https://gammarupage.vercel.app/about
  활동: https://gammarupage.vercel.app/activities
  작품: https://gammarupage.vercel.app/games
- 위 정보는 저장된 동아리 소개와 활동 기록이야. 과거 활동을 현재 확정된 행사로 말하지 마.
- 현재 회원 수·예산·필요 물품 수량·향후 행사 일정·장소·담당자 연락처는 미확인이야.
  겜마루가 법인·사업자·창업팀이라고 가정하거나, 수상·협약·기존 후원 실적을 만들지 마.
- 매 실행 시 사이트의 최신 ‘동아리 정보’를 읽어 이 배경을 갱신해줘.

[3. 수집 기준 — 동아리가 실제로 받을 자원]
우선순위는 다음과 같아.
1) 동아리 또는 대표 명의로 받을 수 있는 운영비·활동비·행사비.
2) 겜마루 자체 행사·활동에 대한 기업의 현금·간식·음료·상품·인쇄물 등 후원.
3) 공동 사용 PC·모니터·개발 장비의 기증·대여와 행사 공간 지원.
4) 동아리 조직에 제공되는 라이선스·협업 도구·서버 자원. 개인 계정 혜택은 제외.

게임 회사에 한정하지 마. 학생 단체를 지원하는 기업·재단·공공기관·대학의 공식 자료도 조사해줘.
진행 중인 지원사업과 우리가 직접 제안할 기업 후원 후보를 각각 찾아줘.
후원 후보에는 유사 동아리·행사 지원 사례, 공식 제안 창구, 요청할 자원과 제안할 협력 내용을 적어줘.
로고 노출·작품 시연·사용 후기 등은 운영진이 검토할 제안안으로만 쓰고 이미 약속한 것처럼 말하지 마.

추천 전에는 제공자, 동아리 수혜 자격, 받을 자원과 공동 사용처, 현재 신청·제안 경로,
우리 쪽 비용·정산·홍보·반납 등의 의무를 공식 원문으로 확인해줘.
조건·금액·수량이 없으면 ‘미확인’으로 적고 추측하지 마.
과거 후원 사례는 현재 모집 공고가 아니야. 공식 연락처도 후원을 받겠다는 확약은 아니야.
자격·창구가 미확인인 후보는 신청 추천에서 빼고 추가 확인 대상으로만 다뤄줘.

다음은 기본 제외야.
- 외부 공모전·창업경진대회·해커톤에 참가하거나 수상해야 받는 상금.
- 일반 무료 행사·세미나·교육·네트워킹·경품 이벤트.
- 개인 학생 계정의 할인·라이선스·클라우드 크레딧·장학금.
- 일반 게임 배포·데모 등록 안내, 채용공고, 업계 뉴스.
- 필수 사업자·창업팀·지역 조건을 겜마루가 충족한다는 근거가 없는 지원.

‘우리가 여는 게임잼에 기업이 간식을 후원’하는 것은 적합한 방향이야.
‘우리가 다른 게임잼에 참가해서 상금을 노림’은 이번 조사의 대상이 아니야.
이 예시는 선별 기준이며, 실제 후원처를 찾았다는 뜻은 아니야.
무료 상품 정가를 확보한 현금으로 더하거나, 확인되지 않은 지출을 절감액으로 계산하지 마.

보류·진행 중인 항목은 메모를 바탕으로 막힌 조건을 추가 조사하고 실제 변화가 있을 때만 보고해줘.

다시 다룰 만큼 중요한 변화가 있다면 현재 기준에 맞는지 확인하고 changeNote에 근거를 적어줘.
사용자가 저장한 상태·메모는 네가 바꾸지 마.

[5. 보고서에 담을 내용]

B. 후원 제안 후보: 지원 사례와 공식 창구가 확인된 기업 최대 2개. 아직 확보한 자원이 아님을 표시.
C. 이어서 검토: 보류·진행 항목에서 새로 확인한 점, 아직 막힌 조건, 다음 행동.
D. 조사한 범위와 미확인 사항. 운영진 확인이 꼭 필요한 질문만 남겨줘.

우리 쪽 부담 / 오늘 할 행동 하나 / 공식 원문과 확인 시각을 담아줘.
창구가 미확인인 과거 후원 사례를 매일 반복하거나 조건을 나열해 분량을 채우지 마.
적합한 신규 자원이 없으면 ‘오늘 확인된 신규 자원 없음’이라고 보고해줘.
검색에 실패한 경우는 ‘조사 미완료’로 구분해줘.

[6. HTML 생성과 발행]
최신 Design.md를 따라 읽기 쉬운 한국어 HTML을 만들어줘.
모바일 한 열, 본문 16px 이상, 짧은 문단을 사용하고 핵심 자원·조건·행동을 먼저 보여줘.
긴 근거만 접고 자격·비용·마감·불확실성은 항상 보이게 해줘.
실행 JavaScript나 상태 변경 폼을 만들지 마. 사이트의 기존 버튼이 진행 상태를 저장해.
Design.md에 맞는 비실행 JSON 데이터 블록(#gammaru-opportunities)을 포함해줘.
version은 1, stateVersion은 최신 조사 기록 값, opportunities는 본문과 일치시켜줘.
audience를 쓰면 ‘club’, category를 쓰면 ‘support’야. status·note는 넣지 마.
항목이 없는 날에도 opportunities: []를 넣고, 기존 항목은 ID·원문을 유지해줘.

한국시간 오늘 날짜가 이미 previousReports와 등록 완료 화면에 있으면 중복 발행하지 마.
발행 직전 전체 조사 자료를 다시 읽고 상태·메모가 바뀌었으면 내용과 JSON을 함께 갱신해줘.
UTF-8·2MB 이하 HTML 파일을 업로드해. 파일 선택이 어려우면 ‘파일 대신 HTML 내용 붙여넣기’를 사용해줘.
오늘 날짜·제목·300자 이내 요약을 입력하고, 채널 알림을 켠 뒤 미리보기에서 내용을 검수해줘.
문제가 없으면 확인 체크 후 ‘이 HTML 등록하기’를 눌러줘.
날짜 충돌·검증 오류·버전 충돌은 원인을 해결하고, 덮어쓰기나 같은 요청 반복으로 우회하지 마.
이 작업은 HTML을 기존 사이트에 올리는 방식이야. 사이트 코드 수정이나 매일 재배포는 필요 없어.
```

## 진행 기록과 매일 발행

HTML에 포함된 비실행 JSON을 사이트가 파싱하여 항목을 연결한다. 관리자와 승인된 구독자가 보고서의
**기회 목록** 또는 `/reports/progress`에서 보류·진행 중·완료·안함 버튼을 한 번 눌러 저장한다.
상태별 필터도 한 번에 선택하며, 자세한 조건과 메모는 펼쳐 본다. 메모 입력은 선택이고 따로 저장한다.
상태는 날짜와 별개로 동일 항목의 ID에 연결되어 다음날에도 유지된다.
업로드 계정은 `/reports/research-state`에서 이 기록을 읽을 수 있지만 상태를 변경할 수 없다.
상태를 저장하는 것과 실제 자금조달 행동을 승인·실행하는 것은 별개다.

최신 지시문은 업로드 로그인 후 `/reports/instructions`에서도 읽을 수 있다.
이 기능의 최초 배포 후에는 **HTML 한 파일 업로드만으로** 새 보고서·진행 항목·Discord 알림이 연결된다.
알림 봇을 Dishost로 분리해도 dots가 사용하는 사이트와 업로드 절차는 같다.
외부 봇 모드에서는 발송 확인까지 기본 60초가 걸릴 수 있다. 대기가 줄지 않으면 봇 실행·연결 상태를
운영자에게 알리고 새 보고서나 새 알림을 반복 생성하지 않는다.

## AI 우선순위와 남은 연결

수집·보고의 주 경로는 사용자의 dots다. 추가 OpenAI API 키나 서버로 복사한 Codex 인증 파일을 요구하지 않는다.
계정에서 dots 사용 가능 여부와 사용량, 클라우드 브라우저의 파일 생성·업로드 지원을 확인해야 한다.

팩트챗 API를 2순위로 쓰는 요구는 유지한다. 이전 독립 시제품에 팩트챗 대체 제공자는 있지만,
**현재 Vercel HTML 보관함에는 자동 조사 스케줄러·팩트챗 자동 대체가 연결되지 않았다.**
`FUNDING_FALLBACK_ENABLED`만 설정해도 Vercel에서 대체 조사가 실행되는 것은 아니다.
실행 승인·메일 전송도 별도 후속 연동 대상이다. 이번 경로는 완성 HTML의 등록·열람과 링크 알림을 담당한다.
